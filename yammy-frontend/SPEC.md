# Спецификация проекта Yammy

Документ описывает контекст приложения, требования к качеству и оптимизации, UI-кит и визуальные константы. Используется для согласованной разработки и как контекст для AI-ассистентов.

---

## 1. Контекст проекта

**Yammy** — мобильно-ориентированное дейтинг-приложение (PWA/адаптивный веб). Пользователь листает карточки профилей (свайп влево/вправо), ставит лайки и дизлайки, общается в чатах. Критичны плавность интерфейса, отзывчивость жестов и быстрая загрузка — любая задержка или лаг напрямую влияют на опыт.

Ключевые сценарии: лента карточек (swipe feed), профили, чаты, уведомления, настройки и авторизация. Все экраны должны быть быстрыми, предсказуемыми по поведению и визуально единообразными.

---

## 2. Требования к качеству и оптимизации

### 2.1 Общие принципы

- **SOLID и KISS**: чёткое разделение ответственности, простые и читаемые решения. Логика выносится в хуки и утилиты, компоненты остаются тонкими.
- **Чистый код**: без мёртвого кода, явные имена, типизация (TypeScript), единый стиль (ESLint, Prettier).
- **Скорость в приоритете**: каждый UI- и логический кусок должен быть спроектирован и реализован с учётом производительности.

### 2.2 UI-задачи

- **Компоненты**: переиспользуемые, с минимальным числом ре-рендеров. Использовать `memo` там, где пропсы стабильны; стабильные колбэки — через `useCallback`/ref, чтобы не ломать мемоизацию детей.
- **Анимации и жесты**: только необходимые, без лишних кадров. Framer Motion — через motion values и `useTransform`, а не через стейт там, где достаточно реактивных значений. Пороги и длительности — в константах/конфиге.
- **Списки и ленты**: виртуализация при больших списках; рендерить только видимые карточки/элементы. Изображения — ленивая загрузка и оптимизированные форматы/размеры.
- **Доступность**: семантика (кнопки, ссылки, формы), фокус, `aria-*` где нужно, контраст цветов.

### 2.3 Логика и данные

- **Запросы**: кэширование (например, React Query), дедупликация, инвалидация по смыслу. Не дублировать запросы и не дергать API без необходимости.
- **Стейт**: локальный стейт только там, где нужен; глобальный/серверный — через выбранное хранилище. Избегать каскадных ре-рендеров из-за подъёма стейта или нестабильных зависимостей.
- **Хуки**: бизнес- и UI-логика в кастомных хуках с явными типами возврата и зависимостей; хуки переиспользуемы и тестируемы.

Любая новая фича должна проходить проверку: «не тормозит ли это список/ленту/чаты и не усложняет ли код без необходимости».

## 3. UI-кит

### 3.1 Стек и паттерны

- **React** + **TypeScript**, сборка — **Vite**.
- **Tailwind CSS** (v4) с CSS-переменными в `src/shared/styles/index.css`.
- **shadcn/ui** (стиль **new-york**), база — **Radix UI**; иконки — **Lucide**.
- **Компоненты**: варианты через **CVA** (`class-variance-authority`), композиция через **Radix Slot** где нужна композиция (например, `asChild`). Утилита классов — `cn()` из `@shared/lib/mergeClass`.

Пример паттерна кнопки (эталон для других компонентов):

- Варианты `variant` и `size` задаются через `cva()`.
- Базовые стили: скругление, типографика, переходы, отключённое состояние, фокус, инвалид.
- Опционально: `asChild` (Slot), `isLoader` (состояние загрузки). Пропсы типизированы (`VariantProps<typeof buttonVariants>` + расширение `ComponentProps<'button'>`).

Новые UI-компоненты должны следовать этому подходу: варианты через CVA, семантика и доступность, минимум лишних обёрток и ре-рендеров.

### 3.2 Основные цвета

Бренд-цвет приложения — **розовый/пудровый**:

| Назначение           | Светлая тема    | Использование                            |
| -------------------- | --------------- | ---------------------------------------- |
| **Primary (акцент)** | `#FF6BA4`       | Кнопки CTA, ссылки, активные элементы    |
| **Primary hover**    | `#FF6BA4` / 90% | Hover кнопок default                     |
| **Primary active**   | `#FF6BA4` / 80% | Active кнопок default                    |
| **Primary border**   | `#FF6BA4`       | Контур кнопки `white-pink`, фокус-кольцо |

В коде (например, `button.tsx`): вариант `default` — `bg-[#FF6BA4]`, `white-pink` — `text-[#FF6BA4] border-[#FF6BA4]`, кольца фокуса — `ring-[#FF6BA4]/50`. Остальной интерфейс опирается на семантические переменные из `index.css`:

- **background / foreground** — фон и основной текст.
- **card / card-foreground** — карточки (в т.ч. карточки свайпа).
- **muted / muted-foreground** — второстепенный текст и фоны.
- **accent / accent-foreground** — подсветка и hover.
- **destructive** — ошибки, удаление.
- **border / input / ring** — границы, поля ввода, фокус.

Тема переключается классом `.dark` на корне; переменные заданы для светлой и тёмной темы в `index.css`.

### 3.3 Типографика

- **Шрифт**: **Bounded** (семейство из `public/fonts/`), веса 200–900; fallback — `system-ui, sans-serif`.
- В `body` задано: `font-family: 'Bounded', system-ui, sans-serif`.
- Начертания подключаются в `src/shared/styles/fonts.css` (ExtraLight, Light, Regular, Medium, SemiBold, Bold, ExtraBold, Black + Variable).

В компонентах используются классы Tailwind по весу (`font-light`, `font-medium` и т.д.) и размеру (`text-sm`, `text-base` и т.д.); для кнопок по умолчанию — `text-sm font-light`.

### 3.4 Радиусы и отступы

- Базовая переменная: `--radius: 0.625rem` (10px); производные: `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl` (см. `@theme` в `index.css`).
- В UI-ките: кнопки — **полное скругление** (`rounded-full`), карточки и блоки — `rounded-2xl`, поля ввода — `rounded-md`. Сохранять единообразие с существующими экранами (например, dashboard: хедер/навигация `rounded-2xl`).

### 3.5 Компоненты из китa

- **Button** — варианты: default (розовый), black, white, white-pink, destructive, outline, secondary, ghost, link; размеры: default, xs, sm, lg, icon, icon-xs, icon-sm, icon-lg.
- **Input** — текстовое поле с border, focus ring, placeholder и disabled; стили через Tailwind и переменные (input, ring, destructive).
- **Avatar**, **Icon**, **Image** — медиа и иконки; использовать в карточках и профилях.
- **SwipeCard / SwipeFeed** — лента карточек с жестами; анимации и логика вынесены в хуки, производительность критична.
- **ThemeToggle** — переключение светлой/тёмной темы.
- **ErrorBoundary** — обработка ошибок рендера.

Новые примитивы (модалки, тосты, списки и т.д.) должны опираться на те же переменные, шрифт и радиусы и при необходимости расширять CVA-варианты по аналогии с кнопкой.

## 4. Структура и алиасы

- Сборка и стили: Vite, Tailwind, CSS-переменные в `src/shared/styles/`.
- Алиасы (например, в `components.json`): `@shared` — компоненты/общее, `@shared/lib` — утилиты, `@shared/ui` — UI, `@shared/hooks` — хуки. Импорты вида `@/shared` используются для публичного API приложения.

---

## 5. Краткий чеклист для новых фич

1. **Скорость**: не добавлять лишних ре-рендеров и тяжёлых анимаций; списки/ленты — виртуализация или ограничение числа узлов.
2. **UI-кит**: цвет и типографика из переменных и Bounded; кнопки/карточки — в духе существующих вариантов и радиусов.
3. **Логика в хуках**: сложная логика и стейт — в кастомных хуках с явными типами возврата.
4. **Чистота кода**: без неиспользуемого кода, с типизацией и прохождением ESLint/Prettier.

При сомнениях по дизайну или производительности — сверяться с этой спецификацией и с реализациями `Button`, `SwipeFeed` и глобальными стилями в `index.css` и `fonts.css`.
